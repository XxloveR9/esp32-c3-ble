# 参数与排障详解

> 本文是 [首页 README](../README.md) 的补充版，把每一项参数背后的原理和每一种故障的成因都写清楚。

---

## 一、为什么需要「校准」

### 1.1 蓝牙鼠标只有相对位移

HID 鼠标的输入报告里没有绝对坐标，只有「相对上一帧移动了多少」（dx / dy）。
所以设备**永远不知道光标当前在屏幕的哪个位置**，只知道「让它往右挪 30」。

这带来两个后果：

1. 光标位置会随着操作不断累积、漂移；
2. 光标一旦顶到屏幕边缘被系统钳住，就再也动不动了 —— 此后每次操作都从边缘开始。

### 1.2 怎么解决：用「撞墙」反推绝对位置

设备采用的办法是**撞边钳位**：

```
1. 往左上角猛推 20 帧（-127, -127）→ 光标必然被钳在屏幕左上角 (0,0)
2. 从 (0,0) 往右下偏移固定的量 (parkX, parkY) → 落在一个确定、可复现的起手点
```

第 1 步之后，「光标离屏幕顶部多少」这个绝对量就被确定了，第 2 步再把它加回去，
于是每次操作的起点都一模一样，不会越滑越贴边。

> 代价是每次动作前多花约 150ms 做归位（推 20 帧 + 分步移动）。这是纯相对鼠标唯一可靠的定位手段。

### 1.3 单位换算是未知的

`parkX` / `parkY` / `滑动距离` 的单位是 **HID 位移单位**，不是像素。
一个单位等于多少像素，取决于手机系统设置的**指针灵敏度**，各家差别很大：

| 指针灵敏度 | 1 个位移单位 ≈ | 2400px 屏幕 ≈ 多少单位 |
|:---|:---|:---|
| 低 | 0.5 px | 4800 |
| 中 | 1.5 px | 1600 |
| 高 | 3 px | 800 |

这就是为什么**必须校准一次**，而不是照着别人的参数抄。

### 1.4 校准的推导

**① 点校准** 找出「点得到视频」的最小偏移 K。
抖音全屏播放时，视频区顶部大约在屏高 8%~10% 处，于是反推：

```
屏高 H ≈ K / 0.10 = 10K
起手 Y = 40% × H
滑动距离 = 18% × H
```

**② 翻页校准** 直接用翻页成功的那个滑动量，覆盖掉推导值。

## 二、安全带（硬保护）

固件里有一条规则：**滑动的起点和终点都必须在安全带内**。

```
顶部禁区 = 屏高 × 10%
底部禁区 = 屏高 × 15%
安全带   = [顶部禁区, 屏高 − 底部禁区]
```

即使参数没校准、或者被改得很离谱，滑动也不会碰到状态栏和导航条。
最坏情况只是「翻不动」，不会出现「退出 APP」「弹出通知栏」这种严重故障。

调试时可以直接看日志：

```
[KEY] ..   起手 y=260 → y=140（安全带 58~425）
```

## 三、落点相关的坑

### 3.1 暂停点到了评论区

抖音全屏播放时，右侧竖着一列按钮：**头像 / 点赞 / 评论 / 收藏 / 分享**。
横向落点落在那一列上，点下去就是打开评论区。

对策：**滑动 X 和点击 X 分开**，默认都设成 `30`（贴屏幕最左侧），
左边是纯画面区，点下去只会暂停。

### 3.2 「鼠标在最右边」

`pushCorner()` 会把光标推到 (0,0)，所以横向位置由 `parkX` 决定。
如果 `parkX` 太大，光标就会停在屏幕右侧 —— 上面那列按钮就在那儿。
把「滑动 X」和「点击 X」都调小到 `20~60` 即可。

### 3.3 上滑变成「返回桌面」

上滑手势的**起点**如果落在屏幕最底部，会被系统当成「从底部上滑」＝ 返回桌面 / 多任务。
所以上滑的起点比中心点要低半个滑动距离（对称起手），必须留在安全带内。

## 四、三种翻页方式

| 方式 | 实现 | 适用场景 |
|:---|:---|:---|
| **鼠标滑动**（默认） | 按住左键 → 分 N 步上下移动 → 松开 | 通用，抖音/快手都能翻 |
| **鼠标滚轮** 🎡 | 直接发 HID 滚轮事件（Generic Desktop 0x38） | 完全不涉及坐标，**永远不会误触系统手势** |
| **键盘方向键** | 发 ↑↓ 键 | ❌ 手机版抖音完全不响应，实测无效 |

滚轮模式在配置页勾选即可，也可以先用「🎡 试滚轮」按钮单测手机认不认滚轮。

> 滚轮必须和鼠标**共用同一个 Report ID**。核心 BLE 库用 UUID 当键存特征表，
> 同一个 `0x2A4D` 只能存在一个 —— 开第二个 input report 会产生野指针，`notify()` 时 assert 崩溃。

## 五、日志怎么读

配置页「🔍 按键日志」和串口（115200）输出完全一致：

```
[KEY] ..   GPIO9 按下
[KEY] ..   单击，等双击判定…
[KEY] ..   起手 y=260 → y=140（安全带 58~425）
[KEY] OK   下一个（上滑） · 单击 · 已发送手势
```

| 日志 | 含义 |
|:---|:---|
| `OK   … 已发送手势` | 报文已成功送到手机，放心去试手机反应 |
| `FAIL 蓝牙未连接，没发出去` | 手机没连蓝牙 |
| `FAIL 手机没订阅通知` | 手机连上了但没把这个设备认成鼠标 → 删掉配对重连 |
| `FAIL 无连接客户端` | BLE 断了 |
| `FAIL GATT发送失败` | 多半是蓝牙没加密 / 没配对成功 |
| `FAIL 校准进行中，先不执行按键动作` | 正在做落点校准，等校准结束 |

## 六、固件结构速查

| 东西 | 位置 | 说明 |
|:---|:---|:---|
| 配置存储 | NVS，命名空间 `vcfg` | 掉电保存；`cfgVer` 字段用于配置迁移 |
| 蓝牙名称 / 热点密码 | 同上，改名要重启 |
| 配对信息 | NVS（核心默认） | OTA 升级不会丢 |
| 固件分区 | No FS 4MB，APP 2MB × 2 | **必须含 OTA**，否则网页升级用不了 |
| 热点 | `192.168.4.1`，密码默认 `12345678` | 设备自己开，不需要路由器 |
| OTA 升级页 | `192.168.4.1/update` | 上传 `firmware.bin` |

### 常用端点

| 端点 | 作用 |
|:---|:---|
| `GET /` | 配置页 |
| `GET /status` | JSON 状态：蓝牙、引脚电平、落点参数、日志 |
| `GET /save?...` | 保存参数（网页是改完即调这个） |
| `GET /raw?k=next\|prev\|click\|wheel\|home` | 单次动作测试 |
| `GET /cal?c=start&mode=1\|2` | 启动校准向导（1=点校准，2=翻页校准） |
| `GET /cal?c=accept` | 确认当前校准档位并保存 |
| `GET /update` | 网页 OTA 升级页 |
| `GET /reboot` | 重启设备 |

## 七、自己改代码

源码是**单文件** `firmware/esp32c3-video-remote.ino`，没有第三方库依赖。

几个可能想改的地方：

| 想改什么 | 改哪儿 |
|:---|:---|
| 按键映射 | `performAction()` 里的 `kind` 1=下一个 2=上一个 3=暂停 |
| 手势判定 | `btnUpdate()`，改 `cfg.longPress` / `cfg.dblClick` |
| 滑动手感 | `doSwipe()`，改步数与间隔 |
| 归位策略 | `parkTo()` / `pushCorner()` |
| 校准档位 | `CAL_K[]` / `CAL_L[]` 两个数组 |
| 网页界面 | `INDEX_HTML` 常量，是一个内嵌的大字符串 |

改完记得同步更新 `webflash/` 里的固件和 `manifest.json` 的 `version` 字段。
